# 44-AI助手框架选型与知识库设计

## 1. 背景与目标
- 不重头开发，基于成熟框架二次开发。
- 面向教学场景：学生在平台进行 Vibe Coding，后端多 Agent 协作，前端可视化编排与结果展示。
- 保持现有架构优势：`Java 控制面 + Go 数据面 + React 前端流程图`。

## 2. 关键结论
- 不建议把 AI 助手核心全部放在前端。
- 前端负责：交互、可视化流程图、执行轨迹展示。
- 后端负责：意图识别、任务规划、多 Agent 调度、工具调用、记忆与权限治理。
- 权威状态在后端：`workflow.json`、代码文件、执行日志、版本号。

## 3. 推荐技术组合（优先）
- 前端 Copilot 交互层：`CopilotKit`
- 多 Agent 编排层：`LangGraph`
- 工具协议层：`MCP`
- 执行层：复用现有 Go 数据面（Docker 沙箱）
- 安全网关：复用现有 Java 控制面（模型代理与密钥管理）

## 4. 与当前项目的映射
- `frontend-platform`：流程图编辑、参数配置、执行回放、结果预览。
- `backend-control-plane`：鉴权、配额、策略、模型代理、工作区元数据。
- `backend-data-plane`：容器生命周期、代码执行、文件注入。
- `proto-contracts`：控制面与数据面协议契约。

## 5. 权限与安全（Harness 风格）
- 路径白名单：仅允许 `/workspace/project/**` 读写。
- 敏感路径禁止：系统目录、密钥文件、`.env`、证书私钥。
- 命令白名单：仅允许测试/构建/运行命令，拒绝高危命令模式。
- 高风险动作审批：删除文件、批量改动、安装依赖需人工确认。
- 双层校验：控制面策略引擎 + 数据面执行前二次校验。

## 6. 知识库系统设计（教学场景）
- 结构化知识层（规则/模板）：
  - Agent 模板、流程模板、课程规则、工具说明。
- 文档检索层（语义）：
  - 教案、历史案例、项目文档、执行复盘。
- 记忆层（分层）：
  - 会话记忆（短期）
  - 项目记忆（长期）
  - 用户偏好与能力画像（教学个性化）

## 7. 最小可落地路线（MVP）
1. 接入 `LangGraph` 替换当前“意图识别 + 规划”。
2. 用 `MCP` 封装文件编辑、命令执行、流程图更新工具。
3. 增加后端权威 `workflow` 版本化与回滚。
4. 增加执行轨迹可视化（每个 Agent 的输入/输出/耗时/工具调用）。
5. 上线混合检索知识库（关键词 + 语义）。

## 8. 风险与对策
- 风险：前后端状态不一致。
  - 对策：执行绑定 `workflow_version`，前端仅展示后端已确认版本。
- 风险：AI 权限过高越权修改。
  - 对策：白名单、审批、审计日志、双层策略校验。
- 风险：多 Agent 成本与延迟上升。
  - 对策：任务分级（轻任务单 Agent，复杂任务多 Agent）。
